# P2.5: diary and reports screens

## What changed
- Routes: `/diary` (general diary, all visible projects, filter in the URL), `/diary/new` (new report; `?project=` preselects), `/diary/[id]/edit` (edit, version history), `/projects/[id]/(tabs)/diary` (project tab, content-only `loading.tsx`) and `/reports/diary` (print or PDF for a chosen project and date).
- Shared logic: `src/features/diary/shared/` (`model.ts` pure helpers, `load.ts` server loaders, `EntryForm`, `DiaryList`, `EntryCard`, `FilterBar`, `PrintByDate`, `diary.css`). `mobile/DiaryMobile` and `desktop/DiaryDesktop` only lay it out; no calculation in the views. `shared/` is not in the WORK_PLAN file list; P2.3 and P2.6 also use `shared/`, so the same was done here.
- Phone: new-report button on top, filter and print folded, list grouped by work date. Desktop: list plus a side column with filter and print by date.
- Form: project, date, text, photos or PDF through the shared `FileUpload` (purpose `diary`, original file kept, 25MB). Edit by the reporter or Ben calls `correctEntry`; Ben also changes project/date through `moveEntry`. Everyone else sees them fixed.
- Cancel (Ben only) goes through `ConfirmDialog` ("saved with all versions, nothing deleted").
- Print: per report and per day (`planReport`, then `/api/reports/diary`, parts and download).
- Permissions are the server's: `canCorrect`, `canMoveOrCancel`, and `report` from `permissions.forProject`. A finished or archived project shows the read-only notice and no write controls. The `tab-motion` order already contained the diary tab, so no change there.
- No migration, service or cost. The "general diary" is the cross-project view (no schema change).
