- אחסון `originals` ו-`display` לפי הפתיח והסכמה הממוזגים: התחלה, אימות תוכן וסיום, קישור ל-60 שניות וקריאת בייטים בהרשאה.
- תת־סוכן נפרד בונה בדיקות חיוביות ושליליות וסוקר את ההפרש. בדיקות Auth ו-Storage ממשיות בענן באחריות מנהל המשימה ותת־סוכן הבדיקה.
- lint, טיפוסים ובנייה לאחר המימוש. אין מסכים ואין בדיקות UI.

## גבולות

אין שינוי סכמה, חוזים, תלויות או CI. אין איפוס או מחיקת נתונים. שינויי הענן המאומתים מפורטים להלן.

## המימוש הנוכחי

- נוספו לקוחות שרת: Data API במפתח פומבי ו-JWT משתמש; מפתח סודי מוגבל ל-Auth admin/token ול-Storage/system RPC. בקשת token בריענון מעבירה IP רק מכותרת Vercel מהימנה.
- כניסה, יציאה מקומית, בדיקת משתמש אצל ספק ו-`get_actor` בכל הקשר, הרשאות פרויקט ו-owner שנבדק מחדש.
- תזמור יצירת חשבון, סנכרון אימייל ואיפוס סיסמה עם ביטול סשנים. אין סיסמה ב-RPC. `createManagedUser` מקבלת שם; בחוזה Platform החסר שם נעשה כרגע שימוש זמני באימייל — ממתין להכרעת שינוי משותף, לא נחשב פתרון סופי.
- אחסון: אסימון TUS ללא upsert, אימות גודל/חתימה ותוכן בשרת, SHA-256, עותק JPEG עד 1600, הורדה אחרי הרשאה בכל בקשה. מקור אינו נכתב מחדש או נמחק.
- נתיבי התחלה/סיום/הורדה, הגנת same-origin לכתיבות, cache פרטי בלבד, proxy לעוגיות HttpOnly ו-400 יום. פורמט ישראלי, חיפוש, RPC ו-fetchAll.

## חסמים שאינם בבעלות P1.3

- `AuthAdmin.createUser` אינו מקבל fullName, בעוד `create_profile` מחייב אותו; נדרש תיאום החוזה עם UsersApi.
- retry אחרי הצלחת `create_profile` וכשל איפוס הסיסמה/ביטול סשנים אינו ניתן לזיהוי בטוח בלי קבלה מתמשכת במסד. ניסיון חוזר נחסם ב-CONFLICT; אין איפוס של חשבון קיים על סמך האימייל בלבד. בדיקת regression נכשלת ומדגימה זאת.
- `get_pending_upload` מחזירה רק pending. אם finish התחייב והתגובה אבדה, ניסיון חוזר לא יכול להחזיר ready לא משויך דרך RLS. אין עקיפת הרשאה בלקוח מנהל; נדרש שינוי משותף.

## ענן

לפי ביצוע מנהל המשימה: נוצרו ואומתו דרך Storage API שני דליים פרטיים: originals, עד 52,428,800 בתים, PDF/JPEG/PNG/WEBP/HEIC/HEIF; ו-display, עד 5,242,880 בתים, JPEG בלבד. לא שונו policies. דרך חזרה ללא מחיקה: להפסיק הנפקת אסימונים; אין למחוק דלי שיש בו נתוני בדיקה.

הגדרות Auth לא שונו: חיבור runtime אינו Management API, והמחבר אינו מספק שינוי config. ביטול הרשמה ו-MFA, IP forwarding ושאר הגדרות 4.1 שבתוקף טרם אומתו; המשימה אינה גמורה.

הבהרת אלון ב-22.11.2026: ״התכוונתי לא להקים שירות מיילים.״ לכן אין דרישת אפס מיילים ואין צורך ב-hook חוסם. הפונקציה הקיימת לא חוברה ולא נמחקה; אין הקמת SMTP או שירות חדש. מנהל הפרויקט מעדכן את המסמכים המשותפים.

## בדיקות וסקירה

- tsc --noEmit ו-lint ממוקד לכל קובצי המימוש עברו ב-Node 24.
- לפי מסירת תת־סוכן הבדיקה: **43 בדיקות מקומיות עברו ובדיקה אחת מסומנת `expected fail`** לחסם retry אחרי כשל סיסמה המתואר לעיל. קבצים: platform ‏16, service ‏5, admin ‏3 עוברות ואחת `expected fail`, clients ‏4, storage/service ‏11, routes ‏4. כיסוי לקוחות ונתיבים כולל עוגיות 400 יום, IP, בידוד המפתח הסודי, CSRF, היעדר סשן, זיוף מבצע ו-no-store בהפניה.
- ההרצות בוצעו עם `vitest run --configLoader runner --project cloud` ובחירת קובצי P1.3. פרטי החיבור נטענים בזמן ריצה דרך `P13_ENV_FILE` ו-`P13_OWNER_FIXTURE`, ללא הצגת ערכים או העתקתם. `expected fail` מתעד תקלה קיימת ואינו מעיד שהיא תוקנה.
- **11 בדיקות ענן עברו**: Auth ‏6 — תפקידים וכספים, פרויקט שהסתיים, זיוף owner, logout, השבתה והפעלה מחדש, יצירה בשם מלא ושינוי אימייל ואיפוס וכניסה דרך השירות. Storage ‏5 — מקור ו-preview וקריאה ישירה ודריסה ומחיקה; תוכן וגודל שגויים; ניסיון חוזר אחרי אובייקט חסר; ביטול גישה ופקיעת קישור אחרי 61 שניות; העלאת PNG מעל 6MiB ב-TUS, עצירה אחרי מקטע ראשון וחידוש. נתוני הבדיקה בדויים ונשארו בענן.
- ממצא הסקירה במיפוי שגיאות תוקן: שדה האימות מתוך details של המסד מוחזר עם הודעה בעברית, רק מתוך רשימת שדות מוכרת; פרטי ספק אינם מוצגים. בדיקת regression נכשלה לפני ועברה אחרי; תת־סוכן הסקירה אישר את התיקון בלי להריץ שוב בדיקה תקפה. טיפוסים ו-lint ממוקד עברו לאחר התיקון.
- סוכן הבדיקה השלים tsc, ‏lint לבדיקות ו-`git diff --check` בהצלחה. הסקירה הושלמה, ללא ממצא חוסם נוסף מעבר לשלושת חסמי החוזים המפורטים. הם נשארים פתוחים ואין אישור מוכנות למיזוג.
