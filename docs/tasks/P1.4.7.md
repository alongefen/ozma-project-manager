# P1.4.7: home and all-projects overview logic

## What changed
- `src/features/overview/logic/{queries,index,actions}.ts`: `OverviewApi` (`getHome`, `getTransferSummary`) per ARCHITECTURE 5.11. Built on injected `ProjectsApi`, `DiaryApi` and `FinanceApi`; no new SQL, migration or service.
- `getHome`: cards come from `listProjects` (RLS-filtered), archived ones dropped. Counters: active projects (status active), reports today (`DiaryApi.getSummary` for the server date), customers (distinct `searchKey(businessName)`), open tasks (sum of card badges). `financeCube` is `null` unless `ctx.actor.isOwner`; for the owner it is the sum of the current month over all projects from `getAllProjectTotals`.
- `getTransferSummary`: `requireOwner` first, then `getAllProjectTotals`; per month `transferAmount` = sum of the projects' already-rounded tax (A-07), with the per-project breakdown; all projects, including finished/archived (FIN-29). Months ascending.
- Finance is not recomputed: amounts are summed from `MonthSummary` values. Only `profitPercentTenths` of the cube is derived locally (same half-away-from-zero rule as `src/lib/money`), because `money` exposes no helper for summing across projects.

## Checked
- `tests/logic/overview/overview.test.ts`, 9 tests, written first (failed on missing module), now passing. `tsc --noEmit` and eslint on the owned files clean.
- Forbidden cases: non-owner (including a manager with finance access) never triggers a finance read for the cube and gets `NOT_FOUND` from the transfer summary before any read; invalid input and dependency failures propagate without partial data.
