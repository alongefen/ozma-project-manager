# P2.6 — single-project finance screens

23.11.2026. Branch `claude/p2-6-finance-94cc9b`. Gates G2/GU passed, not reopened. No migration, service, cost or deployment.

## What changed

- Route `projects/[id]/finance` (server page): reads the book through `FinanceApi.getBook` with the period/day/search filter taken from the URL (default: current month by server date). `NOT_FOUND`, `FORBIDDEN` and a malformed id give a plain 404 with no numbers; a lost session redirects to sign-in. The permission decision is the database's (`viewFinance`); the view never decides.
- **Desktop** (`features/finance/desktop`): demo layout. Filters, three stats, quick-entry panel (quickGrid), transactions table with inline edit row (Enter saves, Escape cancels), "filtered rows" total, period summary and work days; with "all period" a months table linking to each month.
- **Phone** (`features/finance/mobile`): month picker with previous/next, "all period" toggle, three large sums, add/filter/export actions, vertical rows list, month cards for "all period", full-screen entry screen. No table, no tab bar.
- Shared (`features/finance/shared`, outside the literal `mobile/`/`desktop/` globs, as with P1.5 `auth`/`more`): URL query parsing, formatting helpers, draft parsing, `EntryForm`, `Filters`, `ExcelLink`, `finance.css`, `load.ts`.
- All numbers come from the finance logic (`FinanceBook`); the view only formats. Amount text is parsed by `parseShekels` and the fields validated by the contract schema.
- Create/update/cancel go through the existing server actions; one `requestId` per draft so a retry after a lost response cannot duplicate. Cancel needs `canCancel` (owner) and an explicit confirm. Write controls are hidden when `canWrite` is false (finished project: view and print only; the server also refuses with `PROJECT_READ_ONLY`). Export is a link to `/api/exports/finance` with the current filter; Excel link: open for viewers, edit for writers; HTTPS only.

## Follow-up 5: fast filtering (Alon, 23.11.2026)

Branch `claude/p2-6-fast-filter`.

- Default view is the whole period with no filter (`parseFilter` default `all`); the filter popover has no "all period" checkbox: month/year "הכול" means all, and the month chip is the only period chip.
- Search box styled like the other fields (the `type="search"` input had no border) and the same height as the filter button.
- Speed: the page now loads all rows of the period once (`loadFinanceScreen`: base book plus, only when day/search is active, a parallel call for the server-calculated totals). Day and text narrow the rows on screen at once (`visibleRows`, same search key as the server); the URL/server totals follow in the background (debounced 300 ms for typing, `router.replace`). The totals row shows "…" until the server's totals for the shown filter arrive, so nothing is calculated in the view. Period changes still load from the server (instant choice and dimming).
- Remaining slowness is the server round trip itself: `getBook` runs about six database calls one after another (P1.4.6 logic, not touched here). Running the independent ones in parallel would cut every load; proposed as a separate logic change.
- Checked: tsc, eslint, 35 screen tests (default period, local narrowing, hidden cases through the screen loader); fake-data harness: typing narrows rows instantly, input border and button aligned. Not checked: live against the cloud, back-button sync of the filter state (local state wins), phone sheet after this change.
