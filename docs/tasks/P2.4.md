# P2.4: Project documents screens

## What changed
- Route `projects/[id]/(tabs)/files` (page + content-only `loading.tsx`). The tab entry already existed in `sectionsFor` in the right order, so `tab-motion` needed no change.
- Shared layer `src/features/files/shared`: `model.ts` (pure: categories, access draft parsing, counts, filtering, file hrefs), `FilesProvider` (one state for both views), `UploadForm`, `AccessForm`, `AccessPicker`, `DocCard`, `DocList`, `DocTools`, `files.css`.
- Phone `FilesMobile`: categories screen, files screen (back button, no tab bar), upload button at the top. Desktop `FilesDesktop`: category column, list with search. Access is a `Sheet` on both.
- Upload uses the shared `FileUpload` (purpose `document`, original file kept). Category and access must be chosen first; the picker stays locked until both are valid, and access has no default, also for a manager. Candidates come from `listAccessCandidates`. Files that uploaded but failed to save stay listed for a retry.
- Open and download are links to `/api/storage/files/[id]` (signed URL, 60 s, issued by the server per permission).
- Owner only: change access, archive and restore (confirm dialog, nothing deleted), archive view.
- Controls follow `permissions.uploadDocument` / `manageAccess`; the database decides. No logic, migrations or shared files changed.

## Checked
- `tests/screens/files/**` (model + render, 11 tests): access draft validation (no choice refused, selected needs a person, only candidates), counts and filters, controls per role (manager, owner, read-only), no tab list on phone.
- Affected suites `tests/screens`, `tests/logic/files`, `tests/shell`: 142 passed. `npm run typecheck`, `npm run lint`: clean.
- Server-side refusals (non-owner access change, missing access choice, finished project) are the existing P1 tests `tests/logic/files`, `tests/depth/role-matrix.cloud.test.ts`; not re-run here.
