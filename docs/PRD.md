## 1. מטרה

לחברת בנייה וגמר יהיה מקום אחד לניהול הפרויקטים: מה קורה בשטח, מה צריך לבצע, אילו קבצים בתוקף ומה המצב הכספי.

בקשת אלון, במילותיו:

> "building a new webapp project for a new client. the webapp should be easy to use on both mobile and computer. it should have user auth, roles, and permissions. the app should help the client manage his projects, income vs expenses for each project, tasks for each project, work diary for each project and for all projects. files uploaded and organized in catagories. the app should be hebrew native, rtl native."

מדדי הצלחה (**מוצע**):

1. מנהל שטח שולח דיווח עם תמונה מהטלפון בפחות מדקה, בלי הדרכה.
2. בן רואה הכנסות, הוצאות, מקדמה, יתרה ורווח של פרויקט בלי לפתוח Excel.
3. משתמש לא מצליח להגיע למידע שלא הורשה לו, גם לא בקישור ישיר.

## 5. מטריצת תפקיד × פעולה

**כל המטריצה היא הצעה.** שורה עם מספר שאלה עדיין פתוחה, והתא מציג את ההמלצה בלבד.

מקרא:
- **כן**: מותר.
- **לא**: אסור, ונחסם בשרת.
- **משויך**: רק בפרויקט שהמשתמש משויך אליו.
- **הרשאה**: רק אם ניתנה הרשאה מפורשת. מי שאינו מנהל מערכת צריך גם שיוך כשמדובר בפרויקט.
- **רק בן**: בעל העסק. בן תמיד מורשה לכספים ולכל קובץ. מנהל מערכת נוסף, אם ימונה, אינו מקבל אותם אוטומטית.

1. ברירת המחדל היא איסור.

### 10.2 עיגול (פתוח, Q04)

בדמו, שלוש הכנסות חודשיות של 0.17 ₪ נותנות שתי תשובות:

| חישוב | מקדמה | יתרה |
|---|---:|---:|
| סכום שלושת החודשים | 0.03 | 0.48 |
| ״כל התקופה״ | 0.02 | 0.49 |

ההמלצה:
1. שומרים אגורות במספרים שלמים ודוחים יותר משתי ספרות אחרי הנקודה.
2. מחשבים מקדמה לכל חודש ומעגלים לאגורה הקרובה, חצי אגורה הרחק מאפס.
3. ״כל התקופה״ והמצטבר הם סכום החודשים המעוגלים: 0.03 ו-0.48 בדוגמה.
4. אחוז מחושב מהסכומים האלה ומוצג עם ספרה אחת לכל היותר.

### 10.3 זיכויים והחזרים (פתוח, Q04)

הדמו דוחה סכום שלילי ואין בו סוג החזר. מי שרושם החזר מלא של 100,000 כהוצאה נשאר עם מקדמה 3,000 ויתרה −3,000, אף שלא נשארה הכנסה.

| סוג | השפעה |

| הוצאה | מגדיל הוצאות |
| זיכוי מספק | מקטין הוצאות ואינו משנה מקדמה |

חודש יכול לצאת עם מקדמה שלילית המקזזת חודש קודם. כשההכנסות נטו הן אפס או פחות, אחוז הרווח הוא ״—״.
